# Design

This is an Operate surface inside Codewalker’s existing visual system, not a new visual identity. The reference is `../herdr-codewalker-mod/mods/Codewalker/main.js`.

- Host theme and UI font throughout; no private palette. ANSI colors distinguish graph lanes and factual check states.
- 10px outer card radius, 1px theme border; omit the card when the host supplies a frame.
- Two header rows. Row 1 (42px): History/Pull requests (open-PR count in a round pill; the toggle is hidden for a checkout without pull requests), the PR filter when it fits, Refresh. No close button: Esc closes an overlay and the toolbar Git button closes the dock. Row 2 (40px): branch switcher (repository path in its tooltip) with the All branches toggle beside it, Pull/Push with incoming/outgoing counts. Below 500px the PR filter takes a third row. The branch picker turns row 2 into its search field. No separate list-title row. PRs load with the repository, so the count is ready before the tab is opened.
- 40px detail header carries the item's actions; 36px load-more rows; 26px status footer. Horizontal padding 14px, control gaps 8px (10px in the header).
- Every list shares one left edge: 14px gutter, a 13px icon or lane-0 column, 8px gap. PR and branch icons sit in their own column so the lines below the title align with it.
- 13px panel text; 12px semibold section/row headings; 11px metadata; 10px compact status labels. Monospace is reserved for object IDs and Git output.
- Codewalker’s 26px controls, 22px small controls, 6px corners, 5px icon/label gaps. Labelled ghost buttons keep a border. Segmented controls use a 26px outer frame and 20px segments.
- Commit rows: 48px, two lines, 12px lane spacing, lane 0 centered at 6px, 8px nodes. Ref labels drop `HEAD ->`; the ring marks HEAD. Native paths show topology rather than text approximations. HEAD is a ring. No decorative animation.
- PR rows: 68px. Title (12px/16px) and byline (11px/14px: dim `#number`, author, head → base) are one tight pair, as in commit rows; the status line sits 5px below: CI dot and label, a dim separator, review state. Failures and requested changes are the only colored text. Drafts dim their icon and title. PR details group title and size, then review and CI, then the description, then checks as left-aligned rows with a state dot, then comments. Comments load after the details and never delay them. They show newest first, separated by 1px rules: author (12px semibold), dim age, a review-verdict pill, and a small GitHub link. Inline threads add a monospace `path:line` and Resolved/Outdated pills, and they dim when either applies. Replies indent behind a 2px rule. Only the newest 40 render. Remote images do not load in Herdr's Markdown view and leave a blank gap, so comments and PR descriptions show each image as its alt text, linked to the surrounding link or the image. Code blocks are left as written. Do not collapse these facts into an unsupported “ready to merge” claim.
- Details stack below the list at narrow widths and sit beside it at 760px+. A draggable divider splits the list from the details. Beside, the list keeps a sidebar's width (34% of the panel, 300–420px, at least 260px) and the details take the rest, at least 360px. Below, the details open at half the height (180–440px) and the list keeps at least 96px. Commit rows lay out for the list's own width. The dragged size is saved per orientation in `localStorage` and survives a restart; a saved size shrinks to leave the other side room. Long refs and subjects truncate without displacing actions. High-fanout graphs scroll horizontally rather than dropping lanes.
- Commit details: subject and message (Markdown, so hard-wrapped bodies reflow), then facts in a 64px label column (author, committer when different, parents as buttons that select them, refs as pills), then changed files: status letter, file name, dim folder, +/− counts. Merges compare with their first parent and say so. View diff (opens Codewalker commit review beside the followed pane) and Copy ID in the header. Without Codewalker, View diff is hidden and the files group says to install it. Never raw `git show` text.
- A checkout without a GitHub remote has no PR surface at all, rather than an error. PR load failures for a GitHub checkout name one cause (no default repository, not signed in, gh missing) with its fix and a copyable command; the filter is hidden when it cannot help. Raw gh output appears only for unknown causes.
- Branch switches and network writes use an inline confirmation, with repository and destination. There is no surprise modal and no silent checkout.
- List event handlers belong on `on_item_click`, never inside a deferred row renderer. Virtual lists fill a relative parent, with an overlaid scrollbar; a flex-only native list can collapse even when its initial description passes.
